# iPad mini 1 Wi-Fi: tethered recovery and NFS

This contribution pairs CLI 0.1.11 with hardware 0.1.11. Install both local
wheels while these branches await publication. The hardware package supplies
the P105 resources required by the adapter.

The `p105` adapter supports `iPad2,5` / P105AP running the qualified jailbreak
on iOS 9.3.5 build 13G36. It stages the verified kloader and plaintext iBEC over
a UDID-bound SSH proxy, waits for the same ECID in Recovery, then sends the
private bundle and staging loader once. Reconnect the USB cable when prompted.

Recovery reports its provisioned ECID and the live kernel boot ID over USB.
That ECID comes from the owner's verified iOS selection. P105 supplies panel
calibration through MtCl; J71b supplies a live ADT. SSH bootstrap pins the
recovery host key through the physical serial console. Saved credentials are
scoped to the selected device and boot.

The adapter supports status, bounded diagnostics and a handoff to the owner's
existing USB NFS export. Internal storage preparation awaits a qualified A5
storage backend. Keep the host serving NFS throughout the desktop session.

Physical qualification reached the Omarchy desktop and preserved the RAM USB
rescue console through repeated boots. Touch remains slow. One repeat required
a touchscreen service restart after calibration failed; that driver issue
remains open. See the companion hardware validation record for the measured
scope. Diagnostic readiness reports the reached systemd targets; inspect
diagnostics and individual services when input fails.

## Prepare the private recovery

Use the P105 resources from the companion hardware contribution. In
`minimal-linux`, `p105/build-base.py` builds the signed ARMv7 Alpine package
base. Its ARM64 package manager uses the official ARMv7 signing keys and
extracts target packages without executing them. Retain its base receipt.

`p105/prepare-recovery.py` combines that base with an explicit owner initramfs,
the matching panel calibration and the verified target record. The hardware
producer recognizes its `etc/orchard/p105.json`, keeps the desktop kernel
prerequisites, and selects a USB gadget whose serial number carries the boot
identity. The RAM environment waits for an authenticated NFS request.

```sh
python3 p105/build-base.py --output /private/p105/alpine-base.tar
python3 p105/prepare-recovery.py \
  --base /private/p105/alpine-base.tar \
  --base-receipt /private/p105/alpine-base.json \
  --initramfs /private/p105/owner-initramfs \
  --calibration /private/p105/owner-MtCl.bin \
  --target /private/p105/target.json \
  --output /private/p105/recovery-root
```

Build that root through the installed hardware package's `kernel/p105/build`,
passing it as `--private-initramfs` with the separate `--calibration` input.
The resulting components and their receipt stay private. Compose their boot
directory with the installed CLI:

```sh
orchard p105-manifest --components /private/p105/components \
  --ibec /private/p105/iBEC.autogo --kloader /private/p105/kloader \
  --output /private/p105/boot
```

This creates an owner-local `boot.toml` and copies the verified boot assets.
The resolver requires local files and the manifest's private flag for this
boot method. The qualified iBEC and kloader hashes are checked again before
staging. A changed component receipt or another device's ECID stops the boot.

## Owner configuration

Set `ORCHARD_P105_CONFIG` to an owner-only JSON file, or place it at
`ORCHARD_HOME/private/p105.json`. Its `schema` is 1. The required fields are:

| Field | Owner input |
| --- | --- |
| `target` | Object containing the selected `udid` and integer `ecid` |
| `tools` | Directory containing `ideviceinfo`, `iproxy`, `irecovery`, and `sshpass` when password authentication is used |
| `ios.known_hosts` | Private file containing the trusted iOS key under alias `p105-ios-usb` |
| `ios.identity` or `ios.password_file` | Explicit owner-only SSH identity or password file |
| `components` | Directory containing the verified private recovery components |
| `firmware_root` | Owner initramfs with the pinned firmware destinations |
| `calibration` | Object containing `file`, integer `ecid` and the capture's `sha256` |

All paths are absolute. Keep the calibration capture and configuration bound
to the same iPad. `orchard --profile p105 capture-inputs --output FILE` writes
a protected MtCl record after checking the selected device. Private mixins
accept this record with `--inputs`; J71b retains its `--adt` input.

The host also needs SSH, `ssh-keygen`, `showmount` and Podman for preparation.
USB utilities can come from the owner's vetted Legacy iOS Kit installation.
Provisioning the jailbreak and trusting the initial iOS SSH key remain owner
setup steps.

## Boot and hand off

Prepare the Arch ARMv7 root with the hardware runtime's `p105-systemd-v1`
marker and Python 3.9 or later. Export it over NFSv3/TCP to `10.55.0.2`.
The host address is `10.55.0.1/24` on the selected USB link.

```sh
orchard --profile p105 boot /private/p105/boot/boot.toml \
  --nfs-root 10.55.0.1:/absolute/exported/root
orchard --profile p105 status
orchard --profile p105 diagnostics
```

Omit `--nfs-root` to stop in RAM recovery. Provision its first diagnostic
session with `orchard --profile p105 status --recovery`. A later
`orchard --profile p105 handoff --nfs-root HOST:/PATH` uses the saved session.

The host verifies the requested export before dispatch. Recovery accepts one
handoff per boot and validates the systemd root before moving mounts. The
installed root receives the hardware payload and RAM diagnostic keys. A
separate diagnostic listener keeps the serial-pinned key through the pivot;
the root's existing SSH configuration retains its own files beneath the
temporary authorization bind mount. The physical rescue console runs from RAM.

Host reports preserve an uncertain outcome before each upload or handoff.
After an uncertain upload, inspect the device and return to iOS before starting
a fresh attempt. A timeout while waiting for the cable can continue from iBEC:
repeat the same command within 15 minutes. Orchard requires the newest saved
attempt to be awaiting iBEC, with matching ECID and boot files. An upload phase
with an unknown outcome blocks continuation. Uploads and NFS requests receive
one dispatch per attempt.

## Host link ownership

Orchard obtains the network interface and its MAC from the selected USB
device's registry or sysfs children while checking its device and boot identity.
This handles macOS reporting a masked MAC through `ifconfig`. An existing host
address is retained. A missing address can be added with the host's normal
administrator prompt; its private
`network.json` records ownership. After shutting down Linux, run:

```sh
orchard p105-network-cleanup --record /path/to/this/boot/network.json
```

Cleanup removes an address only when that record says Orchard added it. The
owner continues to manage the existing NFS export and its service.
